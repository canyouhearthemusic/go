## Требования к каждому крупному разделу

- В конце — блок **«Что важно для Senior»** из 3–5 пунктов. **[обязательно]**
- У каждой фичи или изменения указана версия Go.
- Есть объяснение «почему так», а не только «что».
- Хотя бы одна диаграмма или таблица там, где есть структура, фазы или сравнение.
- Советы, заблуждения и грабли стоят рядом с механизмом, к которому относятся (если по разделу они есть). Оформление:

````markdown
> **Совет.** <что сделать> — когда <ситуация>. Эффект: <число из запуска>. Не нужно, если <условие>.

> **Заблуждение:** «...». На самом деле ... Это было верно до Go 1.X, потому что ... С 1.Y ...

**Грабли: <короткое название>**

```go
// минимальный код, воспроизводящий ошибку
```

```text
<реальный вывод: panic, неверный результат, go vet, -race>
```

Почему так: ... Как заметить: <линтер / go vet / симптом в production>. Как исправить: ...
````

## Оформление примеров

Код и его реальный вывод идут парой:

````markdown
```go
func BenchmarkBefore(b *testing.B) { ... }
func BenchmarkAfter(b *testing.B)  { ... }
```

```text
BenchmarkBefore-11   352194   3460 ns/op   25208 B/op   12 allocs/op
BenchmarkAfter-11    501642   2290 ns/op    8192 B/op    1 allocs/op
```
````

После вывода — одна-две фразы, что из него следует.
