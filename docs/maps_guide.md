# map в Go: практическое руководство

Всё, что нужно знать о картах при повседневном использовании. Внутреннее устройство (swiss table, группы, control word, рост) разобрано отдельно в [swiss_map.md](swiss_map.md).

Всё поведение ниже проверено запуском на Go 1.26.

## Создание

```go
var m map[string]int              // nil, писать нельзя
m := map[string]int{}             // пустая, писать можно
m := make(map[string]int)         // то же самое
m := make(map[string]int, 1000)   // с запасом места под 1000 записей
m := map[string]int{"a": 1}       // литерал
```

`make` с размером — единственная бесплатная оптимизация. Место выделяется сразу, и вставка 1000 записей пройдёт без единой перестройки карты.

## nil-карта

Читать можно, писать нельзя.

| Операция на nil-карте | Результат |
|---|---|
| `len(m)` | `0` |
| `m["нет"]` | нулевое значение |
| `v, ok := m["нет"]` | `0, false` |
| `delete(m, "x")` | ничего не делает |
| `clear(m)` | ничего не делает |
| `for range m` | ноль итераций |
| `m["x"] = 1` | **паника** `assignment to entry in nil map` |

Частая ошибка: поле-карта в структуре, созданной через `var s Struct` или `&Struct{}`, остаётся nil, и первая же запись паникует.

```go
type Cache struct{ items map[string]int }

c := &Cache{}
c.items["a"] = 1                        // паника

c := &Cache{items: map[string]int{}}    // так правильно
```

## Чтение

Отсутствующий ключ не ошибка — возвращается нулевое значение типа.

```go
v := m["нет"]          // 0 для int, "" для string, nil для слайса
v, ok := m["нет"]      // ok говорит, была ли запись
```

Форма с `ok` нужна, когда нулевое значение — законное значение:

```go
if v, ok := m[k]; ok {
    // ключ есть, даже если v == 0
}
```

## Какие типы можно в ключ

Ключ должен быть **сравнимым** через `==`.

**Можно:** числа, строки, `bool`, указатели, каналы, интерфейсы, структуры и массивы из сравнимых типов.

**Нельзя:** слайсы, карты, функции. Компилятор не пропустит.

**Опасный случай** — `any` или интерфейс в ключе. Компилятор пропустит, паника случится в рантайме:

```go
m := map[any]int{}
m["строка"] = 1        // ок
m[[]int{1}] = 1        // паника: hash of unhashable type []int
```

### NaN

```go
m := map[float64]int{}
m[math.NaN()] = 1
m[math.NaN()] = 2
m[math.NaN()] = 3

len(m)             // 3
m[math.NaN()]      // 0 — ни одну не найти
delete(m, math.NaN())
len(m)             // всё ещё 3
```

`NaN != NaN`, поэтому каждая вставка создаёт новую запись, и достать их нельзя ничем, кроме `range`. Если ключи — `float64` из вычислений, проверяй на NaN перед вставкой.

## Чего нельзя делать

```go
type P struct{ X int }
m := map[string]P{"a": {1}}

m["a"].X = 2      // ошибка компиляции: cannot assign to struct field m["a"].X in map
p := &m["a"]      // ошибка компиляции: элемент карты не адресуем
m1 == m2          // ошибка компиляции: карты нельзя сравнивать
cap(m)            // ошибка компиляции: cap для карт не определён
```

Причина одна: **при росте карта переносит все записи в новую память**, поэтому у элемента нет постоянного адреса.

Обходные пути для структуры в значении:

```go
p := m["a"]; p.X = 2; m["a"] = p   // прочитать, изменить, записать

m := map[string]*P{"a": {1}}       // или хранить указатели
m["a"].X = 2                       // так работает
```

При этом `m[k]++`, `m[k] += x`, `m[k] = append(m[k], v)` работают — компилятор превращает их в чтение и запись.

Сравнить две карты: `maps.Equal(m1, m2)`.

## Итерация

```go
for k, v := range m { }
for k := range m { }
```

**Порядок случайный и меняется от запуска к запуску.** Это сделано специально, чтобы никто не полагался на порядок. Рандомизируется даже стартовая позиция.

Стабильный порядок:

```go
for _, k := range slices.Sorted(maps.Keys(m)) {
    fmt.Println(k, m[k])
}
```

Что происходит при изменении карты во время итерации:

| Действие | Гарантия |
|---|---|
| добавили запись | может появиться в итерации, а может нет |
| удалили запись, которую ещё не прошли | **не появится** |
| изменили значение | вернётся новое значение |
| ничего не трогали | каждая запись вернётся ровно один раз |

Проверено: карта из 10 записей, на первой же итерации удаляем остальные 9 — итерация выдаёт ровно 1 запись.

Удалять текущий ключ во время итерации безопасно:

```go
for k, v := range m {
    if v == 0 { delete(m, k) }
}
```

### Порядок при выводе

`fmt` с Go 1.12 **сортирует** ключи при печати, и `encoding/json` тоже:

```go
m := map[int]string{3: "c", 1: "a", 2: "b", 10: "j"}
fmt.Println(m)               // map[1:a 2:b 3:c 10:j]
json.Marshal(m)              // {"1":"a","2":"b","3":"c","10":"j"}
```

Это касается только вывода. Сам `range` остаётся случайным.

## Удаление и память

```go
delete(m, k)     // удалить одну запись
clear(m)         // удалить все (Go 1.21+)
```

**Карта никогда не уменьшается.** После `delete` всех записей или `clear` она занимает столько же памяти, сколько занимала на пике. `len` станет 0, память останется.

Вернуть память можно только созданием новой карты:

```go
m = make(map[string]int)     // старая уйдёт сборщику мусора
```

Важно для долгоживущих кешей: карта, в которую час подкладывали записи и потом всё удалили, продолжит держать память.

## Карты передаются по ссылке — но не совсем

```go
func add(x map[string]int) { x["b"] = 2 }

m := map[string]int{"a": 1}
add(m)
// m == map[a:1 b:2]   — изменение видно
```

Присваивание самой переменной внутри функции на вызывающего не влияет:

```go
func reset(x map[string]int) { x = nil }
reset(m)
// m по-прежнему не nil
```

В функцию передаётся копия указателя на внутреннюю структуру. Через неё можно менять содержимое, но не саму переменную.

Отсюда же: **копирования карты через присваивание не бывает**.

```go
a := map[string]int{"x": 1}
b := a
b["x"] = 2
// a["x"] == 2 — это одна и та же карта

b := maps.Clone(a)     // вот это настоящая копия
```

`maps.Clone` — копия **поверхностная**. Если значения слайсы или указатели, они общие:

```go
deep := map[string][]int{"x": {1, 2}}
dc := maps.Clone(deep)
dc["x"][0] = 999
// deep == map[x:[999 2]]
```

## Конкурентность

**Карта не защищена от одновременного доступа.** Одновременные чтение и запись из разных горутин — не race condition с непредсказуемым значением, а **аварийное завершение программы**:

```
fatal error: concurrent map read and map write
fatal error: concurrent map writes
```

Это `fatal error`, его нельзя перехватить через `recover`. Runtime старается такие случаи ловить, но гарантии нет — надёжно их находит только `go test -race` / `go run -race`.

Одновременное чтение из нескольких горутин без записи безопасно.

### Как защищаться

```go
type Counter struct {
	mu sync.Mutex
	m  map[string]int
}

func (c *Counter) Inc(k string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.m[k]++
}
```

`sync.RWMutex` — если чтений сильно больше, чем записей.

### sync.Map

Готовая потокобезопасная карта, но **не универсальная замена**. По документации она выигрывает в двух случаях:

1. Ключ пишется один раз, а читают его много (кеш, который только растёт).
2. Разные горутины работают с непересекающимися наборами ключей.

В остальных случаях обычная карта с мьютексом быстрее. Плюс `sync.Map` не типизирована — всё через `any`.

Практическое правило: начинай с мьютекса, переходи на `sync.Map` только если профайлер показал, что мьютекс — узкое место.

## Пакет maps (Go 1.21+)

```go
maps.Clone(m)                    // поверхностная копия
maps.Equal(m1, m2)               // сравнение
maps.Copy(dst, src)              // скопировать записи из src в dst
maps.DeleteFunc(m, f)            // удалить по условию
maps.Keys(m)                     // итератор ключей (Go 1.23+)
maps.Values(m)                   // итератор значений

slices.Collect(maps.Keys(m))     // ключи слайсом
slices.Sorted(maps.Keys(m))      // ключи слайсом, отсортированные
```

## Производительность

Что реально помогает:

1. **`make` с размером.** Карта растёт, перестраивая себя целиком; каждый рост — перенос всех записей. Знаешь размер — укажи.
2. **Не хранить большие структуры значением, если часто читаешь.** Каждое чтение копирует значение. Для больших структур — указатель.
3. **`map[T]struct{}` вместо `map[T]bool` для множеств.** `struct{}` занимает 0 байт.

```go
set := map[string]struct{}{}
set["a"] = struct{}{}
if _, ok := set["a"]; ok { }
```

4. **Избегать долгоживущих карт с огромным числом указателей**: сборщик мусора обходит все указатели в карте. `map[int]int` для GC бесплатна, `map[string][]byte` на миллион записей — заметная нагрузка.

Что знать про внутренности:

- Ключ или значение больше 128 байт хранятся отдельно, а в карте лежит указатель на них.
- С Go 1.24 карты устроены как swiss table и заметно быстрее старых, особенно на больших размерах.
- Стоимость чтения не зависит от размера карты: миллион записей читается так же быстро, как тысяча.
- Одна вставка может оказаться медленной, если попала на перестройку. Объём одной перестройки ограничен ~900 записями независимо от размера карты.

Подробности — в [swiss_map.md](swiss_map.md).

## Частые паттерны

**Множество:**
```go
seen := map[string]struct{}{}
if _, ok := seen[x]; !ok {
    seen[x] = struct{}{}
}
```

**Подсчёт:**
```go
count := map[string]int{}
for _, w := range words { count[w]++ }   // нулевое значение избавляет от проверки
```

**Группировка:**
```go
byAge := map[int][]Person{}
for _, p := range people {
    byAge[p.Age] = append(byAge[p.Age], p)   // append к nil-слайсу работает
}
```

**Вложенные карты** — внутреннюю нужно создавать явно:
```go
m := map[string]map[string]int{}
if m["a"] == nil { m["a"] = map[string]int{} }
m["a"]["b"] = 1
```

Часто проще ключ-структура:
```go
type key struct{ A, B string }
m := map[key]int{}
m[key{"a", "b"}] = 1
```

**Значение по умолчанию:**
```go
func get(m map[string]int, k string, def int) int {
	if v, ok := m[k]; ok { return v }
	return def
}
```

## Шпаргалка ошибок

| Симптом | Причина |
|---|---|
| `assignment to entry in nil map` | забыл `make` или литерал |
| `hash of unhashable type []int` | в ключ `any` попал слайс, карта или функция |
| `concurrent map writes` | две горутины пишут без мьютекса |
| `concurrent map read and map write` | горутина читает, пока другая пишет |
| `cannot assign to struct field m[k].F` | значение-структура не адресуемо; читай, меняй, записывай обратно |
| тесты падают через раз | код полагается на порядок `range` |
| память не освобождается | `delete`/`clear` не уменьшают карту |
| изменения в копии видны в оригинале | `b := a` не копирует карту; нужен `maps.Clone` |
| `maps.Clone` не помог | клон поверхностный, вложенные слайсы общие |
| ключ вставился, но не находится | ключ — NaN |
